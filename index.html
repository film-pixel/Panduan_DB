📖 Bagian 1: Pengenalan Database

1.1 Apa Itu Database?

Database (Basis Data) adalah kumpulan data yang disimpan secara terstruktur dan sistematis di komputer. Database memungkinkan kita menyimpan, mencari, mengubah, dan menghapus data dengan mudah.

💡 Analogi Sederhana
🧠 Bayangkan ini:
• Database = Sebuah lemari arsip besar di kantor
• Tabel = Satu laci dalam lemari itu (misal: laci surat, laci faktur)
• Kolom (Field) = Kolom isian di formulir (Nama, Tanggal, Jumlah)
• Baris (Record) = Satu formulir yang sudah diisi lengkap
• Primary Key = Nomor urut unik di setiap formulir
🎯 Kenapa harus pakai Database? Kenapa tidak Excel saja?
1. Kapasitas: Excel mentok di ~1 juta baris, MySQL bisa miliaran baris
2. Akses bersamaan: Database bisa diakses banyak user sekaligus tanpa konflik
3. Keamanan: Database punya sistem user & password, Excel hanya password file
4. Validasi: Database bisa menolak data yang salah format secara otomatis
5. Relasi: Database bisa menghubungkan data antar tabel dengan mudah

1.2 Komponen Utama Database

KomponenPenjelasan SederhanaContoh Nyata
EntitasObjek/benda yang datanya mau disimpanSiswa, Buku, Mobil, Produk
AtributCiri-ciri dari entitasNama_siswa, Judul_buku, Harga
Primary KeyID unik, seperti NIK di KTPNIS, Kode_barang, ID_pelanggan
Foreign KeyPenghubung ke tabel lainID_buku di tabel Peminjaman
RelasiHubungan antar entitasSiswa MEMINJAM Buku
📝 Istilah Penting untuk PPLG:
• DBMS = Software pengelola database (MySQL, PostgreSQL, Oracle)
• SQL = Bahasa untuk berkomunikasi dengan database
• CRUD = Create, Read, Update, Delete (4 operasi dasar)
• Schema = Struktur/desain database (tabel, kolom, relasi)

⚙️ Bagian 2: Instalasi XAMPP

2.1 Apa itu XAMPP?

XAMPP adalah paket software yang berisi: Apache (web server), MySQL/MariaDB (database), PHP (bahasa pemrograman), dan phpMyAdmin (alat kelola database). Semua dalam satu instalasi!

1 Download XAMPP
  1. Buka browser, kunjungi: https://www.apachefriends.org
  2. Pilih versi sesuai OS kamu (Windows, Linux, Mac)
  3. Klik tombol Download (pilih yang versi PHP 8.x terbaru)
  4. Tunggu download selesai (±150 MB)
🤔 Kenapa harus XAMPP? Kenapa tidak install MySQL sendiri?
XAMPP sudah menyatukan Apache + MySQL + PHP + phpMyAdmin. Kalau install sendiri-sendiri, kamu harus konfigurasi manual yang rumit. XAMPP sudah di-set supaya semua komponen langsung bisa bekerja sama.
2 Install XAMPP
  1. Double-click file installer yang sudah didownload
  2. Klik Next terus sampai selesai (jangan ubah setting default)
  3. Pilih folder instalasi (default: C:\xampp)
  4. Tunggu proses instalasi selesai
🤔 Kenapa install di C:\xampp? Tidak boleh di tempat lain?
Boleh di mana saja, tapi hindari folder yang ada spasinya (seperti "Program Files") karena bisa menyebabkan error di beberapa konfigurasi. Path pendek seperti C:\xampp lebih aman.
3 Menjalankan Apache & MySQL
  1. Buka XAMPP Control Panel dari desktop/start menu
  2. Klik tombol Start di baris Apache
  3. Klik tombol Start di baris MySQL
  4. Tunggu sampai keduanya berubah menjadi tulisan Running berwarna hijau
🤔 Apa fungsi Apache dan MySQL?
• Apache = Web server yang "melayani" permintaan dari browser. Tanpa Apache, kamu tidak bisa membuka phpMyAdmin
• MySQL = Database server yang menyimpan data. Ini "otak" penyimpanannya
Keduanya harus menyala (Running) agar phpMyAdmin bisa diakses.
🧠 Analogi: Apache = Pelayan restoran (menerima pesanan), MySQL = Dapur (tempat masak/menyimpan bahan)
4 Membuka phpMyAdmin
  1. Buka web browser (Chrome/Firefox/Edge)
  2. Di address bar, ketik: http://localhost/phpmyadmin
  3. Tekan Enter
  4. Halaman phpMyAdmin akan muncul!
🤔 Apa artinya "localhost"?
localhost artinya "komputer ini sendiri". Jadi kamu mengakses server yang berjalan di komputermu sendiri, bukan di internet. Tidak perlu koneksi internet untuk mengakses phpMyAdmin!
⚠️ Masalah yang Sering Terjadi & Solusinya:
• Apache tidak mau start? → Cek apakah ada Skype, Zoom, atau IIS yang pakai port 80. Tutup aplikasi itu dulu
• MySQL tidak mau start? → Cek port 3306. Bisa juga hapus file ibdata1 di folder C:\xampp\mysql\data
• "Access Denied" saat buka phpMyAdmin? → Username: root, Password: (kosongkan)

📝 Bagian 4: Merancang Database

🚨 JANGAN PERNAH membuat database tanpa rancangan! Seperti membangun rumah tanpa denah. Akibatnya fatal: data berantakan, duplikat di mana-mana, sulit dikembangkan.

4.1 Tahapan Merancang Database

1 Tentukan Tujuan
Tentukan dulu: Database ini untuk aplikasi apa? Siapa yang akan pakai? Data apa yang akan dikelola?
Contoh: "Saya mau buat sistem perpustakaan sekolah untuk mengelola buku, anggota, dan peminjaman."
🤔 Kenapa harus tentukan tujuan dulu?
Tanpa tujuan jelas, kamu akan bingung tabel apa saja yang dibutuhkan. Bisa-bisa kamu membuat tabel yang tidak penting, atau malah kurang tabel yang penting.
2 Identifikasi Entitas
Cari tahu "benda" atau "konsep" apa saja yang datanya perlu disimpan.
Dari contoh perpustakaan: Buku, Anggota, Peminjaman, Kategori.
Setiap entitas ini nantinya akan menjadi satu tabel.
🤔 Gimana cara mengidentifikasi entitas?
Lihat kata benda dalam deskripsi sistem. Kalau ada kata "menyimpan data X" atau "mencatat Y", maka X dan Y adalah entitas.
3 Tentukan Atribut (Kolom)
Untuk setiap entitas, tentukan data spesifik apa yang perlu disimpan.
Contoh entitas Buku: judul, pengarang, penerbit, tahun_terbit, ISBN, stok.
Setiap atribut ini akan menjadi satu kolom dalam tabel.
🤔 Berapa banyak kolom yang ideal?
Tidak ada batasan pasti. Tapi prinsipnya: simpan hanya data yang dibutuhkan sistem. Jangan menyimpan data "siapa tahu nanti perlu" — itu boros dan bikin tabel gemuk.
4 Tentukan Primary Key
Pilih satu kolom yang unik untuk setiap record. Biasanya berupa id_[entitas] dengan tipe INT dan AUTO_INCREMENT.
Contoh: id_buku, id_anggota, id_peminjaman.
🤔 Kenapa harus ada Primary Key?
Primary key menjamin setiap baris data punya identitas unik. Tanpa primary key, kamu tidak bisa membedakan dua data yang isinya sama persis. Selain itu, primary key diperlukan untuk membuat relasi antar tabel.
5 Tentukan Relasi
Tentukan bagaimana hubungan antar entitas:
• One-to-One (1:1): 1 Siswa punya 1 NIS
• One-to-Many (1:N): 1 Anggota bisa pinjam BANYAK buku
• Many-to-Many (N:N): 1 Buku bisa dipinjam BANYAK anggota, butuh tabel bantuan
🤔 Kenapa relasi penting?
Relasi menghubungkan data. Misal kamu ingin tahu "buku apa yang sedang dipinjam Budi". Tanpa relasi, kamu harus menyimpan semua data di satu tabel (boros dan kacau). Dengan relasi, cukup hubungkan tabel Anggota dan Buku lewat tabel Peminjaman.

🔢 Bagian 5: Memahami Tipe Data

5.1 Kenapa Tipe Data Penting?

Tipe data menentukan jenis nilai yang bisa disimpan di sebuah kolom. Salah pilih tipe data = boros memori, error saat input, atau hasil perhitungan yang tidak akurat.

📌 Tipe Data Numerik (Angka)
TipeUkuranRentangDigunakan Untuk
TINYINT1 byte-128 s/d 127Umur, rating, status (0/1)
SMALLINT2 byte-32rb s/d 32rbJumlah halaman, stok kecil
INT(11)4 byte-2M s/d 2M⭐ Primary Key, Foreign Key, jumlah
DECIMAL(10,2)VariabelPresisi sempurna⭐ HARGA, UANG, GAJI
FLOAT4 bytePresisi rendahStatistik, persentase
🤔 Kenapa harga harus pakai DECIMAL? Kenapa tidak INT atau FLOAT?
• INT tidak bisa menyimpan koma (Rp 10.500 tidak bisa)
• FLOAT bisa menyimpan koma, tapi tidak presisi. Rp 10.500,00 bisa jadi Rp 10.499,9999 — ini merugikan!
• DECIMAL(10,2) menjamin presisi sempurna. (10,2) artinya 8 digit bulat + 2 digit desimal
📌 Tipe Data String (Teks)
TipeMaksDigunakan Untuk
CHAR(5)255 charData panjang TETAP (kode pos, NIS, gender M/F)
VARCHAR(255)65.535 char⭐ Data panjang BERVARIASI (nama, email, judul)
TEXT65.535 charDeskripsi, artikel, alamat panjang
🤔 CHAR vs VARCHAR: Apa bedanya?
• CHAR(10) menyimpan "Budi" → tetap pakai 10 karakter (ditambah spasi). Lebih cepat tapi boros
• VARCHAR(10) menyimpan "Budi" → hanya pakai 4 karakter. Lebih hemat
Pakai CHAR kalau panjang data SELALU sama. Pakai VARCHAR kalau panjang data BERVARIASI.
📌 Tipe Data Tanggal & Waktu
TipeFormatContoh Penggunaan
DATEYYYY-MM-DD⭐ Tanggal lahir, tanggal pinjam
DATETIMEYYYY-MM-DD HH:MM:SSWaktu transaksi lengkap

🤔 Kenapa format tanggal MySQL YYYY-MM-DD? Kenapa tidak DD-MM-YYYY?
Format YYYY-MM-DD adalah standar internasional (ISO 8601). Keuntungan: bisa di-sorting dengan benar (2024-01-01 < 2024-12-31). Kalau DD-MM-YYYY, sorting akan kacau.

📐 Bagian 6: Normalisasi Database

6.1 Apa Itu Normalisasi?

Normalisasi adalah teknik untuk menghilangkan data ganda (redundansi) dalam database. Tujuannya agar database efisien, konsisten, dan mudah di-maintenance.

1 Bentuk Tidak Normal (UNF) — Data Awal
Bayangkan kita simpan semua data dalam satu tabel:
SALAH | Nama | Kelas | Judul Buku | Pengarang | Tgl Pinjam | |--------|----------|-----------------|-----------|------------| | Budi | XII PPLG | MySQL Guide | Ahmad | 2024-01-10 | | Budi | XII PPLG | PHP Basics | Susi | 2024-01-10 | | Ani | XII PPLG | MySQL Guide | Ahmad | 2024-01-12 |
🤔 Masalah apa yang terlihat?
• Data "Budi" dan "XII PPLG" ditulis berulang → boros tempat
• Kalau Budi pindah kelas, harus update banyak baris → rawan lupa
• Kalau hapus peminjaman Ani, data "MySQL Guide" ikut hilang → data loss
2 First Normal Form (1NF) — Data Atomik
Syarat: Setiap kolom hanya berisi satu nilai (tidak boleh array/list).
1NF | id | Nama | Kelas | Judul Buku | Pengarang | Tgl Pinjam | |----|--------|----------|-----------------|-----------|------------| | 1 | Budi | XII PPLG | MySQL Guide | Ahmad | 2024-01-10 | | 2 | Budi | XII PPLG | PHP Basics | Susi | 2024-01-10 | | 3 | Ani | XII PPLG | MySQL Guide | Ahmad | 2024-01-12 |
🤔 Sudah 1NF, tapi masih ada masalah?
Ya! Data Budi-XII PPLG masih muncul 2x. Data Ahmad juga 2x. Ini masih redundan. Perlu lanjut ke 2NF.
3 Second Normal Form (2NF) — Hilangkan Ketergantungan Parsial
Syarat: Pisahkan data yang hanya bergantung pada SEBAGIAN primary key.
2NF - Tabel terpisah Tabel Anggota: Tabel Buku: Tabel Peminjaman: | id | Nama | Kelas | | id | Judul | Pengarang | | id | id_agt | id_buku | Tgl | |----|------|-------| |----|-------|-----------| |----|--------|---------|------| | A1 | Budi | XII | | B1 | MySQL | Ahmad | | P1 | A1 | B1 | ... | | A2 | Ani | XII | | B2 | PHP | Susi | | P2 | A1 | B2 | ... |
🤔 Apa keuntungannya?
Sekarang data anggota dan buku hanya disimpan sekali. Tabel peminjaman hanya menyimpan ID sebagai penghubung. Kalau Budi pindah kelas, cukup update 1 baris di tabel Anggota.
4 Third Normal Form (3NF) — Hilangkan Ketergantungan Transitif
Syarat: Kolom non-key tidak boleh bergantung pada kolom non-key lain.
3NF - Tambah tabel Kategori Tabel Kategori: Tabel Buku (revisi): | id | nama_kategori | | id | judul | pengarang | id_kategori (FK) | |----|---------------| |----|-------|-----------|------------------| | 1 | Pemrograman | | B1 | MySQL | Ahmad | 1 | | 2 | Desain | | B2 | UI/UX | Dian | 2 |
🤔 Kenapa kategori harus dipisah?
Jika kategori disimpan langsung di tabel buku (sebagai teks), maka setiap ganti nama kategori harus update banyak baris. Dengan tabel terpisah, cukup update 1 kali di tabel Kategori.

🏗️ Bagian 7: Membuat Database Baru

1 Buka Tab Database
Di halaman utama phpMyAdmin, klik tab "Database" di bagian atas.
🤔 Kenapa harus buat database dulu? Tidak bisa langsung buat tabel?
Database adalah "wadah" untuk tabel. Semua tabel harus disimpan di dalam database. Ibaratnya: sebelum taruh rak (tabel) di gudang, kamu harus punya ruangannya (database) dulu.
2 Isi Nama Database
Di kolom "Nama database", ketik: db_perpustakaan
(Gunakan huruf kecil, tanpa spasi, tanpa simbol khusus)
🤔 Kenapa namanya db_perpustakaan? Kenapa tidak "Database Perpustakaan"?
• Tidak boleh ada spasi dalam nama database
• Awalan db_ adalah standar agar mudah dikenali sebagai database
• Snake_case (huruf kecil + underscore) adalah standar industri
3 Pilih Collation
Di dropdown "Collation", pilih: utf8mb4_general_ci
🤔 Apa itu Collation? Kenapa harus utf8mb4?
Collation adalah aturan pengurutan dan perbandingan karakter.
• utf8mb4 = Mendukung semua karakter dunia termasuk Arab, China, Jepang, dan emoji 😊🚀
• general_ci = Case Insensitive (tidak bedakan huruf besar/kecil saat search)
Kalau pakai latin1, data dengan karakter khusus akan error atau jadi tanda tanya (???)
4 Klik Create
Klik tombol Create. Database baru akan muncul di sidebar kiri.
🧠 Analogi: Kamu baru saja membuat "ruangan" baru di gudang. Sekarang ruangan sudah siap, tinggal pasang rak-nya (tabel).
📝 Alternatif via SQL:
SQL CREATE DATABASE db_perpustakaan CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

Klik Go
🤔 Kenapa pakai prefix tb_? Kenapa tidak langsung "buku"?
Awalan tb_ menandakan bahwa ini adalah tabel. Di project besar, ini membantu membedakan tabel dari view, stored procedure, atau function. Standar yang banyak dipakai di Indonesia.
3 Mengisi Detail Kolom
Isi form seperti tabel di bawah. Perhatikan setiap pilihan dengan teliti.
NameTypeLengthDefaultIndexA_I
id_bukuINT11(none)PRIMARY✅
kode_bukuVARCHAR10(none)UNIQUE-

🤔 Penjelasan Setiap Pilihan:
• A_I (AUTO_INCREMENT) ✅: Angka akan naik otomatis (1,2,3...). Centang ini hanya untuk id_buku. Kenapa? Karena kita tidak mau repot mengisi ID manual. MySQL yang akan mengisikan otomatis.
• PRIMARY KEY: Menandakan kolom ini adalah identitas unik. Tidak boleh kosong, tidak boleh duplikat.
• UNIQUE: Tidak boleh duplikat, tapi BOLEH kosong (NULL). Cocok untuk kode_buku dan NIS.
• Default NULL: Kalau tidak diisi, nilainya kosong. Cocok untuk data opsional.
• Default 0: Kalau tidak diisi stok, otomatis 0. Ini masuk akal karena stok tidak mungkin NULL.
4 Klik Save
Scroll ke bawah, klik tombol Save (atau Go). Tabel akan dibuat dan muncul di sidebar kiri.
🤔 Apa yang terjadi saat Save?
MySQL mengeksekusi perintah CREATE TABLE. phpMyAdmin mengirimkan perintah SQL ke MySQL, lalu MySQL membuat file fisik untuk menyimpan struktur dan data tabel. File ini ada di folder C:\xampp\mysql\data\db_perpustakaan\

✏️ Bagian 9: Mengisi Data ke Tabel (INSERT)

Setelah tabel dibuat, saatnya mengisi data. Operasi ini disebut INSERT (bagian dari CRUD: Create).

1 Buka Tab Insert
Klik tabel tb_buku di sidebar, lalu klik tab "Insert" di bagian atas.
🤔 Kenapa ada 2 baris form kosong?
phpMyAdmin menyediakan 2 baris supaya kamu bisa langsung mengisi 2 data sekaligus. Lebih efisien! Kalau hanya mau isi 1, cukup isi baris pertama saja.
2 Isi Data Buku
Isi kolom-kolom berikut (lewati id_buku karena AUTO_INCREMENT):
  • kode_buku: BK001
  • judul: Belajar Database MySQL
  • pengarang: Ahmad Fauzi
  • penerbit: Gramedia
  • tahun: 2024
  • stok: 5
🤔 Kenapa id_buku tidak diisi?
Karena kita sudah centang AUTO_INCREMENT, MySQL akan otomatis mengisi angka 1 untuk data pertama, 2 untuk data kedua, dan seterusnya. Kalau kamu isi manual, malah bisa bentrok!
3 Klik Go / Simpan
Scroll ke bawah, klik tombol Go. Data akan tersimpan!
🧠 Analogi: Kamu baru saja mengisi satu formulir dan memasukkannya ke dalam laci Buku. Formulir itu sekarang menjadi record/baris di tabel.
4 Cara Insert via SQL (Cara Pro)
Klik tab "SQL", lalu ketik:
SQL INSERT INTO tb_buku (kode_buku, judul, pengarang, penerbit, tahun, stok) VALUES ('BK002', 'Pemrograman PHP', 'Susi Susanti', 'Elex Media', 2023, 3);
Klik Go untuk menjalankan.
🤔 Kenapa belajar SQL juga? Kan sudah ada GUI?
GUI memudahkan, tapi SQL lebih powerful dan cepat. Di dunia kerja, programmer sering menulis SQL langsung. Selain itu, SQL bisa disimpan dalam file untuk backup atau automation.
💡 Tips: Coba isi beberapa data lagi agar tabel tidak kosong. Minimal 5 data buku berbeda. Ini akan berguna untuk latihan SELECT nanti.

👀 Bagian 10: Membaca/Melihat Data (SELECT)

Setelah data masuk, kita perlu melihatnya. Operasi ini disebut SELECT (bagian dari CRUD: Read).

1 Browse Data
Klik tabel tb_buku di sidebar. Secara default, tab "Browse" akan terbuka dan menampilkan semua data.
🤔 Kenapa langsung muncul data? Saya tidak klik apa-apa!
Saat kamu klik nama tabel, phpMyAdmin otomatis menjalankan perintah SELECT * FROM tb_buku. Ini menampilkan semua kolom dan semua baris.
2 Mencari Data Spesifik (Search)
Klik tab "Search". Kamu bisa mencari data dengan kriteria tertentu.
Contoh: Di kolom pengarang, pilih operator LIKE %...%, isi value: Ahmad
Klik Go. Hanya buku dengan pengarang mengandung kata "Ahmad" yang muncul.
🤔 Apa artinya LIKE %...%?
LIKE '%Ahmad%' artinya: cari teks yang mengandung kata "Ahmad" di mana saja.
• % = wildcard (karakter apa saja, berapa pun jumlahnya)
• %Ahmad% = ada Ahmad di tengah/depan/belakang
• Ahmad% = diawali Ahmad
• %Ahmad = diakhiri Ahmad
3 SELECT via SQL
SQL -- Lihat semua data SELECT * FROM tb_buku; -- Lihat buku dengan stok di atas 3 SELECT judul, stok FROM tb_buku WHERE stok > 3; -- Urutkan berdasarkan judul A-Z SELECT * FROM tb_buku ORDER BY judul ASC; -- Tampilkan 3 data pertama SELECT * FROM tb_buku LIMIT 3;
🤔 Kenapa SELECT * tidak disarankan di production?
SELECT * mengambil semua kolom. Kalau tabel punya 50 kolom, data yang diambil banyak dan lambat. Lebih baik sebutkan kolom yang diperlukan saja: SELECT id_buku, judul, stok FROM tb_buku.

🔄 Bagian 11: Mengubah Data (UPDATE)

1 Edit Data via Browse
Di tab Browse, klik ikon ✏️ (pensil) di samping data yang ingin diubah. Ubah nilai, klik Go.
2 UPDATE via SQL
SQL UPDATE tb_buku SET stok = 10, penerbit = 'Gramedia Pustaka' WHERE id_buku = 1;
🤔 Kenapa WHERE sangat penting?
TANPA WHERE, SEMUA baris akan berubah! Contoh: UPDATE tb_buku SET stok = 10; akan mengubah stok SEMUA buku jadi 10. Ini bencana!
WHERE membatasi baris mana yang diubah. Selalu cek ulang WHERE sebelum eksekusi!
🧠 Analogi: WHERE seperti alamat rumah. Kalau kamu bilang "cat semua rumah jadi putih" tanpa alamat, semua rumah akan dicat. Tapi kalau "cat rumah nomor 5 jadi putih", hanya rumah no.5 yang dicat.

🗑️ Bagian 12: Menghapus Data (DELETE)

1 Hapus Data via Browse
Di tab Browse, klik ikon 🗑️ (tempat sampah) di samping data. Konfirmasi dengan OK.
🤔 Apakah data yang dihapus bisa dikembalikan?
TIDAK BISA! Operasi DELETE bersifat permanen. Itulah kenapa sebelum menghapus, pastikan kamu sudah backup database. Di dunia nyata, programmer sering pakai soft delete (tambah kolom deleted_at, isi dengan tanggal. Data tidak benar-benar dihapus, hanya disembunyikan).
2 DELETE via SQL
SQL DELETE FROM tb_buku WHERE id_buku = 5;
⚠️ BAHAYA! DELETE FROM tb_buku; (tanpa WHERE) akan menghapus SELURUH data di tabel!

🔗 Bagian 13: Membuat Relasi (Foreign Key)

1 Pahami Konsep Foreign Key
Foreign Key adalah kolom yang menghubungkan satu tabel ke tabel lain. Foreign key merujuk ke Primary Key di tabel referensi.
🤔 Kenapa pakai Foreign Key? Kenapa tidak copy-paste data saja?
Foreign key menjaga integritas data. Contoh: kamu tidak bisa memasukkan id_buku yang tidak ada di tabel buku ke tabel peminjaman. MySQL akan menolak otomatis. Ini mencegah data "yatim" (data yang merujuk ke sesuatu yang sudah tidak ada).
2 Buat Tabel Peminjaman
Buat tabel tb_peminjaman dengan kolom:
id_pinjam (INT, PK, AI), id_anggota (INT), id_buku (INT), tgl_pinjam (DATE), tgl_kembali (DATE)
3 Atur Foreign Key via Relation View
  1. Buka tabel tb_peminjaman → tab Structure
  2. Klik link "Relation view" di bawah tabel
  3. Di kolom id_anggota, pilih: db_perpustakaan.tb_anggota.id_anggota
  4. ON DELETE: pilih CASCADE, ON UPDATE: pilih CASCADE
  5. Lakukan hal sama untuk id_buku → tb_buku.id_buku
  6. Klik Save
🤔 Apa artinya ON DELETE CASCADE?
Kalau data di tabel induk (tb_buku) dihapus, maka data di tabel anak (tb_peminjaman) yang merujuk ke buku itu juga ikut terhapus otomatis. Ini mencegah data yatim.
Alternatif lain:
• RESTRICT = Tolak penghapusan kalau masih ada data anak
• SET NULL = Jadikan NULL kolom foreign key-nya

🔀 Bagian 14: JOIN Table (Menggabungkan Data)

1 Kenapa Butuh JOIN?
Data tersebar di beberapa tabel yang saling terhubung. Untuk melihat data lengkap (misal: nama peminjam + judul buku), kamu perlu JOIN.
2 Contoh INNER JOIN
SQL SELECT a.nama AS nama_peminjam, b.judul AS buku_dipinjam, p.tgl_pinjam FROM tb_peminjaman p INNER JOIN tb_anggota a ON p.id_anggota = a.id_anggota INNER JOIN tb_buku b ON p.id_buku = b.id_buku;
🤔 Bagaimana cara membaca INNER JOIN?
"Ambil data dari tb_peminjaman (p), lalu cocokkan dengan tb_anggota (a) berdasarkan id_anggota. Kalau cocok, gabungkan barisnya. Lalu cocokkan lagi dengan tb_buku (b) berdasarkan id_buku."
Hasilnya: satu tabel gabungan yang memuat nama peminjam, judul buku, dan tanggal pinjam.
🧠 Analogi: JOIN seperti mencocokkan dua lembar absen. Lembar A berisi NIS dan Nama. Lembar B berisi NIS dan Nilai. Kamu gabungkan berdasarkan NIS, hasilnya: NIS, Nama, dan Nilai dalam satu tampilan.

📦 Bagian 15: Ekspor & Impor Database

1 Ekspor (Backup) Database
  1. Klik database db_perpustakaan di sidebar
  2. Klik tab "Export"
  3. Pilih Quick dan format SQL
  4. Klik Go
  5. File .sql akan otomatis terdownload
🤔 Kenapa harus backup? File .sql itu apa isinya?
File .sql berisi seluruh perintah SQL untuk membuat ulang database kamu dari nol. Isinya: CREATE DATABASE, CREATE TABLE, INSERT INTO, dll. Kalau database rusak atau hilang, kamu tinggal import file ini dan semua data kembali seperti semula.
🧠 Analogi: Ekspor = Fotokopi seluruh isi lemari arsip. Kalau lemari asli terbakar, kamu punya salinannya.
2 Impor (Restore) Database
  1. Buat database baru (atau pilih database yang sudah ada)
  2. Klik tab "Import"
  3. Klik "Choose File" → pilih file .sql
  4. Scroll ke bawah, klik Go
  5. Tunggu sampai muncul pesan sukses
🤔 Kapan perlu impor?
• Pindah komputer (dari laptop sekolah ke laptop pribadi)
• Mengumpulkan tugas dalam bentuk file .sql
• Restore setelah database rusak
