📖 1. Pendahuluan & Konsep Dasar Database

🎯 Capaian Pembelajaran: Memahami konsep database, DBMS, dan peran database dalam pengembangan perangkat lunak.

1.1 Apa Itu Database?

Database (Basis Data) adalah kumpulan data yang terorganisir dan disimpan secara sistematis dalam komputer sehingga dapat diakses, dikelola, dan diperbarui dengan mudah. Dalam konteks PPLG, database adalah komponen backend yang menyimpan semua data aplikasi.

🧠 Analogi untuk Programmer:
• Database = Gudang data aplikasi (seperti array multidimensi yang persisten)
• Tabel = Class/Entity (seperti struct di C/C++ atau class di Java)
• Record/Row = Object/Instance (satu objek dari class)
• Kolom/Field = Property/Attribute (variabel dalam class)
• Primary Key = ID unik (seperti memory address untuk identifikasi)

1.2 DBMS (Database Management System)

DBMS adalah software yang mengelola database. MySQL, PostgreSQL, SQLite, Oracle, SQL Server adalah contoh DBMS. Untuk PPLG, kita fokus pada MySQL/MariaDB karena:

  • ✅ Open Source - Gratis digunakan
  • ✅ Paling populer di industri web (70%+ website pakai MySQL)
  • ✅ Integrasi sempurna dengan PHP, Node.js, Python, Java
  • ✅ Standar industri untuk LAMP/LEMP stack
  • ✅ Dokumentasi lengkap dan komunitas besar

1.3 phpMyAdmin dalam Ekosistem Development

🔧 Posisi phpMyAdmin dalam Stack:
Frontend (HTML/CSS/JS/Vue/React) → Backend (PHP/Node.js) → phpMyAdmin → MySQL Database

phpMyAdmin adalah GUI client untuk MySQL. Dalam development, kamu bisa pakai:
• phpMyAdmin - GUI web, cocok untuk development & admin
• MySQL Workbench - GUI desktop, fitur lebih lengkap
• CLI (Command Line) - Terminal, untuk production/server
• Library ORM - Prisma, Sequelize, Eloquent (diakses dari kode)

1.4 Jenis-Jenis Database

2.3 Konsep ACID dalam Transaksi

🔐 ACID adalah 4 properti yang menjamin transaksi database aman:
• Atomicity (Atomik) - Semua operasi dalam transaksi sukses, atau semua gagal (all-or-nothing)
• Consistency (Konsisten) - Data tetap valid sesuai aturan sebelum & sesudah transaksi
• Isolation (Terisolasi) - Transaksi berjalan seolah hanya sendiri, tidak terganggu transaksi lain
• Durability (Durable) - Data yang sudah di-commit tetap tersimpan meskipun server crash

Contoh Kasus Transfer Uang:
UPDATE rekening SET saldo = saldo - 50000 WHERE id = 1;
UPDATE rekening SET saldo = saldo + 50000 WHERE id = 2;
Kedua query harus sukses atau keduanya gagal. Tidak boleh hanya satu yang sukses!

🔢 4. Tipe Data MySQL - Panduan Lengkap

🎯 Capaian Pembelajaran: Memilih tipe data yang tepat dan efisien sesuai kebutuhan aplikasi.

4.1 Prinsip Pemilihan Tipe Data

  1. Sesuaikan dengan data - Jangan pakai BIGINT untuk umur (cukup TINYINT)
  2. Efisiensi storage - VARCHAR(20) untuk nama kota, bukan VARCHAR(255)
  3. Akurasi perhitungan - DECIMAL untuk uang, jangan FLOAT/DOUBLE
  4. Index-friendly - CHAR lebih cepat di-index daripada VARCHAR

📐 5. Normalisasi Database - Teori & Praktik

🎯 Capaian Pembelajaran: Menerapkan normalisasi 1NF, 2NF, 3NF untuk menghasilkan database yang efisien.

5.1 Mengapa Normalisasi Penting?

Normalisasi menghilangkan anomali data (insert anomaly, update anomaly, delete anomaly) dan redundansi data (data duplikat). Database yang tidak ternormalisasi akan menyulitkan development dan maintenance.

5.2 Bentuk Normal (Normal Form)

📌 Unnormalized Form (UNF) - Data Awal

UNF Tabel: PEMINJAMAN (Belum Normal) ┌──────────┬──────────┬──────────────────────────────────────┬────────────┐ │ id_pinjam│ id_agt │ buku (judul, pengarang, tgl_pinjam) │ tgl_kembali│ ├──────────┼──────────┼──────────────────────────────────────┼────────────┤ │ P01 │ A01 │ MySQL Guide - Ahmad - 2024-01-10, │ 2024-01-17 │ │ │ │ PHP Basics - Susi - 2024-01-10 │ │ │ P02 │ A02 │ MySQL Guide - Ahmad - 2024-01-12 │ 2024-01-19 │ └──────────┴──────────┴──────────────────────────────────────┴────────────┘

Masalah: Kolom "buku" berisi multiple values (tidak atomik), data pengarang diulang, struktur tidak jelas.

📌 First Normal Form (1NF) - Data Atomik

Syarat: Setiap kolom berisi nilai tunggal (atomik), tidak ada repeating group.

1NF ┌──────────┬──────────┬─────────────────┬───────────┬────────────┬────────────┐ │ id_pinjam│ id_agt │ judul_buku │ pengarang │ tgl_pinjam │ tgl_kembali│ ├──────────┼──────────┼─────────────────┼───────────┼────────────┼────────────┤ │ P01 │ A01 │ MySQL Guide │ Ahmad │ 2024-01-10 │ 2024-01-17 │ │ P01 │ A01 │ PHP Basics │ Susi │ 2024-01-10 │ 2024-01-17 │ ⚠️ Duplikat │ P02 │ A02 │ MySQL Guide │ Ahmad │ 2024-01-12 │ 2024-01-19 │ ⚠️ Duplikat └──────────┴──────────┴─────────────────┴───────────┴────────────┴────────────┘

Masalah: Data id_pinjam, id_agt, tgl_kembali diulang-ulang (partial dependency).

📌 Second Normal Form (2NF) - Hilangkan Partial Dependency

Syarat: Sudah 1NF + semua kolom non-key bergantung penuh pada primary key.

2NF Tabel: peminjaman (header) Tabel: detail_peminjaman ┌──────────┬──────────┬────────────┐ ┌──────────┬─────────────────┬───────────┐ │*id_pinjam│ id_agt │ tgl_kembali│ │*id_pinjam│ judul_buku │ pengarang │ ├──────────┼──────────┼────────────┤ │*id_detail │ │ │ │ P01 │ A01 │ 2024-01-17 │ ├──────────┼─────────────────┼───────────┤ │ P02 │ A02 │ 2024-01-19 │ │ P01 │ MySQL Guide │ Ahmad │ └──────────┴──────────┴────────────┘ │ P01 │ PHP Basics │ Susi │ │ P02 │ MySQL Guide │ Ahmad │ ⚠️ Duplikat pengarang └──────────┴─────────────────┴───────────┘

Masalah: Data pengarang masih diulang (transitive dependency: judul → pengarang).

📌 Third Normal Form (3NF) - Hilangkan Transitive Dependency

Syarat: Sudah 2NF + tidak ada ketergantungan transitif (kolom non-key tidak boleh bergantung pada kolom non-key lain).

3NF (Bentuk Final) Tabel: buku Tabel: peminjaman Tabel: detail_peminjaman ┌──────────┬─────────────────┬───────────┐ ┌──────────┬──────────┬────────────┐ ┌──────────┬──────────┬──────────┐ │*id_buku │ judul │ pengarang │ │*id_pinjam│ id_agt │ tgl_kembali│ │*id_detail│ id_pinjam│ id_buku │ ├──────────┼─────────────────┼───────────┤ ├──────────┼──────────┼────────────┤ ├──────────┼──────────┼──────────┤ │ B01 │ MySQL Guide │ Ahmad │ │ P01 │ A01 │ 2024-01-17 │ │ D01 │ P01 │ B01 │ │ B02 │ PHP Basics │ Susi │ │ P02 │ A02 │ 2024-01-19 │ │ D02 │ P01 │ B02 │ └──────────┴─────────────────┴───────────┘ └──────────┴──────────┴────────────┘ │ D03 │ P02 │ B01 │ └──────────┴──────────┴──────────┘

✅ Keuntungan 3NF: Tidak ada data duplikat, update pengarang cukup di satu tempat, insert/delete aman.

💡 Rule of Thumb untuk PPLG:
• Minimum target: 3NF untuk project production
• Ada BCNF (Boyce-Codd NF) dan 4NF, tapi jarang diperlukan untuk aplikasi umum
• Normalisasi berlebihan bisa bikin query kompleks (banyak JOIN). Seimbangkan dengan performa!

⚡ 6. Implementasi Operasi CRUD Advanced

🎯 Capaian Pembelajaran: Mengimplementasikan operasi CRUD lengkap dengan validasi dan best practice.

6.1 CREATE - INSERT dengan Variasi

Insert Single Row:

SQL INSERT INTO tb_buku (kode_buku, judul, pengarang, id_kategori, stok) VALUES ('BKU-0001', 'Database Systems', 'Elmasri', 2, 5);

Insert Multiple Rows:

SQL INSERT INTO tb_buku (kode_buku, judul, pengarang, id_kategori, stok) VALUES ('BKU-0002', 'Clean Code', 'Robert Martin', 1, 3), ('BKU-0003', 'Design Patterns', 'GoF', 1, 2), ('BKU-0004', 'Refactoring', 'Martin Fowler', 1, 4);

Insert dengan SELECT (Copy Data):

SQL -- Backup data buku ke tabel arsip INSERT INTO tb_buku_arsip SELECT * FROM tb_buku WHERE stok = 0;

6.2 READ - SELECT dengan Filter & Sorting

Basic SELECT dengan WHERE, ORDER BY, LIMIT:

SQL -- Cari buku dengan stok di atas 3, urutkan terbaru, ambil 10 data SELECT id_buku, kode_buku, judul, stok FROM tb_buku WHERE stok > 3 ORDER BY created_at DESC LIMIT 10;

SELECT dengan LIKE & Wildcard:

SQL -- Cari buku dengan kata "database" di judul SELECT * FROM tb_buku WHERE judul LIKE '%database%'; -- Cari buku pengarang dimulai dengan "Mar" SELECT * FROM tb_buku WHERE pengarang LIKE 'Mar%';

SELECT dengan Agregasi:

SQL -- Hitung total buku per kategori SELECT k.nama_kategori, COUNT(b.id_buku) AS jumlah_buku, SUM(b.stok) AS total_stok, AVG(b.stok) AS rata_rata_stok FROM tb_buku b JOIN tb_kategori k ON b.id_kategori = k.id_kategori GROUP BY k.id_kategori HAVING COUNT(b.id_buku) > 1 ORDER BY jumlah_buku DESC;

6.3 UPDATE - Update Data dengan Kondisi

Update Single Row:

SQL UPDATE tb_buku SET stok = stok - 1, updated_at = NOW() WHERE id_buku = 5 AND stok > 0;

Update Multiple Rows dengan CASE:

SQL UPDATE tb_buku SET stok = CASE WHEN id_buku = 1 THEN 10 WHEN id_buku = 2 THEN 20 WHEN id_buku = 3 THEN 30 ELSE stok END WHERE id_buku IN (1, 2, 3);

6.4 DELETE - Hapus Data dengan Aman

Soft Delete vs Hard Delete:

SQL -- SOFT DELETE (Rekomendasi!) - Tambah kolom deleted_at UPDATE tb_buku SET deleted_at = NOW() WHERE id_buku = 10; -- HARD DELETE - Hati-hati! DELETE FROM tb_buku WHERE id_buku = 10 AND NOT EXISTS ( SELECT 1 FROM tb_detail_peminjaman WHERE id_buku = 10 );
🚨 WARNING UNTUK PPLG!
• Selalu gunakan WHERE pada UPDATE dan DELETE
• Gunakan soft delete (tambah kolom deleted_at) untuk data penting
• Cek foreign key constraint sebelum DELETE
• Backup database sebelum operasi berbahaya!

6.5 TRANSACTION - Operasi Aman

SQL START TRANSACTION; INSERT INTO tb_peminjaman (kode_pinjam, id_anggota, tgl_pinjam, tgl_jatuh_tempo) VALUES ('PJM-001', 1, CURDATE(), DATE_ADD(CURDATE(), INTERVAL 7 DAY)); -- Ambil ID peminjaman yang baru saja dibuat SET @id_pinjam = LAST_INSERT_ID(); INSERT INTO tb_detail_peminjaman (id_peminjaman, id_buku, jumlah) VALUES (@id_pinjam, 5, 1); UPDATE tb_buku SET stok = stok - 1 WHERE id_buku = 5 AND stok > 0; -- Jika semua sukses, commit. Jika gagal, rollback COMMIT; -- ROLLBACK; -- Jika terjadi error

7.2 Contoh JOIN Lengkap

INNER JOIN - Data Pemimjaman Aktif:

SQL SELECT p.kode_pinjam, a.nama_lengkap, a.kelas, b.judul AS judul_buku, p.tgl_pinjam, p.tgl_jatuh_tempo, DATEDIFF(p.tgl_jatuh_tempo, CURDATE()) AS sisa_hari FROM tb_peminjaman p INNER JOIN tb_anggota a ON p.id_anggota = a.id_anggota INNER JOIN tb_detail_peminjaman d ON p.id_peminjaman = d.id_peminjaman INNER JOIN tb_buku b ON d.id_buku = b.id_buku WHERE p.status = 'dipinjam' ORDER BY p.tgl_jatuh_tempo ASC;

LEFT JOIN - Semua Buku (termasuk yg belum pernah dipinjam):

SQL SELECT b.kode_buku, b.judul, COUNT(d.id_detail) AS total_dipinjam FROM tb_buku b LEFT JOIN tb_detail_peminjaman d ON b.id_buku = d.id_buku GROUP BY b.id_buku ORDER BY total_dipinjam DESC;

Subquery - Anggota yang belum mengembalikan buku:

SQL SELECT nama_lengkap, kelas FROM tb_anggota WHERE id_anggota IN ( SELECT DISTINCT id_anggota FROM tb_peminjaman WHERE status = 'dipinjam' AND tgl_jatuh_tempo < CURDATE() );

🚀 8. Optimasi Database & Index

🎯 Capaian Pembelajaran: Mengoptimalkan performa database dengan index dan teknik optimasi.

8.1 Apa Itu Index?

Index seperti daftar isi buku. Tanpa index, MySQL harus scan seluruh tabel (full table scan). Dengan index, MySQL langsung melompat ke data yang dicari.

📊 Perbandingan Performa:
• Tanpa index: Mencari 1 record di 1 juta data = scan 1 juta row
• Dengan index: Mencari 1 record di 1 juta data = scan ~20 row (B-Tree)
Perbedaan kecepatan: 50.000x lebih cepat!

8.2 Jenis-Jenis Index

TipeDeskripsiKapan Digunakan

UNIQUEIndex unik, boleh NULLEmail, NIS, kode unik
INDEX / KEYIndex biasa, non-uniqueKolom yang sering di WHERE/JOIN
FULLTEXTIndex untuk pencarian teksJudul, deskripsi, artikel
COMPOSITEGabungan beberapa kolomWHERE kolom1 AND kolom2

8.3 Membuat Index

SQL -- Single column index CREATE INDEX idx_judul ON tb_buku(judul); -- Composite index (urutan penting!) CREATE INDEX idx_kategori_stok ON tb_buku(id_kategori, stok); -- Fulltext index untuk pencarian ALTER TABLE tb_buku ADD FULLTEXT INDEX ft_judul_pengarang (judul, pengarang); -- Cara query dengan fulltext SELECT * FROM tb_buku WHERE MATCH(judul, pengarang) AGAINST('database design' IN NATURAL LANGUAGE MODE);

8.4 Analisis Performa dengan EXPLAIN

SQL -- Cek bagaimana MySQL menjalankan query EXPLAIN SELECT * FROM tb_buku WHERE judul LIKE '%mysql%'; -- Perhatikan kolom: -- type: ALL (buruk) → index → range → ref → const (terbaik) -- rows: semakin kecil semakin baik -- key: index yang digunakan (NULL = tidak pakai index)
💡 Best Practice Index:
• Index kolom yang sering muncul di WHERE, JOIN, ORDER BY
• Jangan over-index: setiap index memperlambat INSERT/UPDATE
• Composite index: urutkan dari yang paling selektif
• Gunakan EXPLAIN untuk memeriksa query lambat
• Tabel kecil (<1000 rows) tidak butuh index tambahan
